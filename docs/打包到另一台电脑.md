# 把靶场拷到另一台电脑

面向的场景：带着笔记本去汇报，需要在本机之外跑起 R1。

## 结论先说

**直接复制整个 `若依系统` 文件夹是跑不起来的。** 有三个坑，每个都会让 MySQL 或
Java 起不来，而且报错信息都看不出根因。

用 `python scripts\pack.py` 生成的最小包（约 500 MB）才行。

## 为什么直接复制不行

| 坑 | 实际情况 | 后果 |
|---|---|---|
| **MySQL 数据不在文件夹里** | `mysql/my.ini` 写 `datadir=C:/Users/HZR/ry_r2_mysql/data`，而 `C:/Users/HZR/ry_r2_mysql` 是指向工程内 `mysql/` 的 **junction** | junction 不被复制 → 新机器上 41 张业务表全丢，MySQL 起不来 |
| **JDK / Maven / mysqld 装在工程外** | `lab.local.json` 全是本机绝对路径（`D:/develop/java-se-8u44-ri`、`D:/tools/Python 3.12.9/`） | 新机器没这些路径 → `lab.py` 直接报找不到 |
| **工程 11 GB，大半用不上** | `src` 5.2G / `build` 2.2G / `runtime` 1.9G，其中 `runtime/R1/logs` 单独就 1.1G | U 盘拷很久，且演示只需要其中一小部分 |

## 怎么做

### 第一步：在现在这台机器上打包

```bash
cd C:\Users\HZR\Desktop\若依系统
python scripts\pack.py
```

默认打 R1（演示最常用的那座），输出到 `C:\Users\HZR\Desktop\lab-demo`，约 500 MB。
想换位置或换站点：

```bash
python scripts\pack.py --out E:\lab          # 直接打到 U 盘
python scripts\pack.py R1 R11 C3             # 多打几座
```

打包会剔除所有日志（`.log`）、`__pycache__`、`.git`，只留运行必需的 930 个文件。

### 第二步：拷到笔记本

整个 `lab-demo` 文件夹拷过去，放哪都行（`D:\`、桌面、任意子目录都可以）。
**不用预先改任何配置** —— 路径是在新机器上现算的。

### 第三步：在新电脑上双击 `START-HERE.bat`

它做两件事：

1. **自愈路径**（第一次运行）：重写 `mysql/my.ini` 的 datadir 指向包内实际位置，
   并生成新的 `lab.local.json`（自动探测本机 JDK8 / mysqld / Python 的位置）
2. 启动 R1 并打开浏览器

## 新电脑上还需要装什么

**只有两样**，而且都必须是真的装好、不是绿色版：

| 依赖 | 说明 |
|---|---|
| **JDK 8** | R1 是若依 4.5.1，**只能用 JDK8**。JDK17/21/25 都会启动失败 |
| **MySQL 8.0** | 脚本只用到它的 `mysqld.exe` 二进制，数据目录用包里自带的 |

nginx、Redis 都已经打进包里了，不用另装。

> `--unpack` 会读 JDK 的 `release` 文件确认版本号，所以即使你的 `JAVA_HOME`
> 指向 JDK25 也不会误选（这是实测踩过的坑：VS Code 自带的 JDK25 曾被误认成 JDK8，
> 结果 R1 用 JDK25 启动直接失败）。

如果探测不到，脚本会明确告诉你缺哪个，手工填 `lab.local.json` 即可：

```json
{
  "JDK8":   "D:/develop/java-se-8u44-ri",
  "MYSQLD": "C:/Program Files/MySQL/MySQL Server 8.0/bin/mysqld.exe",
  "PYTHON": "C:/Users/你/AppData/Local/Programs/Python/Python311/python.exe"
}
```

## 已验证到什么程度

打包流程做过**端到端模拟**：把包复制到另一个路径（模拟换机器），跑 `--unpack`
自愈，然后真实启动：

| 验证项 | 结果 |
|---|---|
| `lab.py up R1` | UP，入口 19101 + 后端 19201 都通 |
| 登录页标题 | `登录 - 藤县人民医院门诊管理系统`（与原环境一致） |
| 页面长度 | 3922 字节（与原环境完全相同） |
| 版本指纹 | `version:4.5.1` 正确识别 |
| **登录 admin/admin123** | **成功** —— 证明数据库表结构与数据完整 |

## 演示当天建议

1. **提前一天**在新电脑上跑一遍，确认能起来。第一次启动约 25 秒。
2. 停站用 `python scripts\lab.py down R1`；MySQL/Redis 不会自动停
   （它们可能被别的站共用），需要的话 `python scripts\lab.py down infra`。
3. **兜底方案**：录一段演示视频放 PPT 里。现场环境出问题的概率不为零，
   有视频至少不会卡在那里。

## 一个提醒

包里包含 MySQL 数据文件（`mysql/data/`），里面有靶场的所有业务数据。
这些是虚构数据，但**包体积主要由它和 jar 决定**（`mysql/data` 约 400 MB）。
如果 U 盘紧张，可以只保留 `mysql/data/ry_r1`（R1 用的库），其余 `ry_r*` 是别的站点的。
