# 04 行为契约（不得改动清单）

> **本文件所有条目以官方 tag 源码实测为准**，核验样本 `lab/version_matrix/src/v4.6.2 ~ v4.8.3`。
> 标 `[已核验]` 的逐行查过源码；标 `[待核验]` 的按框架惯例写，实施时必须对照源码回填。

## 为什么有这份文件

这些系统不是孤立运行的。每个站点都有外围系统在对接着：WMS 拉库存、ERP 推单据、移动端 App 调接口、集团单点登录做认证。对接清单是合同附件，路径、参数名、返回体结构任何一项变动都会导致对接失败。

下面列的东西**一个字符都不能改**。二开只能做加法（加模块、加菜单、加表），不能动既有契约。

## 一、单机版（R1 R2 R3 R4 R5，Thymeleaf + Shiro）

### 1.1 验证码接口 `[已核验]`

**`GET /captcha/captchaImage`**

源码 `ruoyi-admin/.../controller/system/SysCaptchaController.java`：

```java
@RequestMapping("/captcha")           // 类级
@GetMapping(value = "/captchaImage")  // 方法级
```

拼出来是 **`/captcha/captchaImage`**。4.6.2 / 4.7.8 / 4.8.0 / 4.8.2 / 4.8.3 五个版本完全一致。

> 不是 `/captcha/image`，也不是 `/captchaImage`。写错就 404，登录页验证码不出来。

登录页引用（`templates/login.html`）：
```html
<img th:src="@{/captcha/captchaImage(type=${captchaType})}">
```

**必须带 `type` 参数**，值取 `math` 或 `char`：

| 请求 | 结果 |
|---|---|
| `/captcha/captchaImage?type=math` | 200，约 2.9 KB JPEG |
| `/captcha/captchaImage?type=char` | 200，约 3.1 KB JPEG |
| `/captcha/captchaImage`（不带参数） | **200 但响应体 0 字节** |

不带 `type` 时 `bi` 保持 null，`ImageIO.write(null, ...)` 抛 `IllegalArgumentException: image == null!`，被 catch 吞掉，对外表现是 200 + 空 body。这是源码原样行为，**不要"修"成默认 math**。

### 1.3 登录提交 `[已核验]`

```
POST /login
Content-Type: application/x-www-form-urlencoded

username=admin&password=admin123&rememberMe=false&validateCode=1234
```

**参数名是 `rememberMe`（驼峰），不是 `rememberme`。**

DOM 里 `<input name="rememberme">` 是全小写，但提交走的是 `ruoyi/login.js` 的 jQuery：

```js
var rememberMe = $("input[name='rememberme']").is(':checked');
$.ajax({ data: { "username": ..., "password": ..., "rememberMe": rememberMe } });
```

实际发出去是驼峰。源码 `SysLoginController.java`：

```java
@PostMapping("/login")
public AjaxResult ajaxLogin(String username, String password, Boolean rememberMe)
```

**按 DOM 的 name 传全小写会 500**：Spring 绑不到 `Boolean rememberMe`，参数为 null，
进 `new UsernamePasswordAuthenticationToken(username, password, null)` 时拆箱 NPE。
用 curl 测试必须用驼峰。

- 成功：302，`Set-Cookie: JSESSIONID=...`
- 失败：回登录页并提示

### 1.4 列表接口 `[已核验]`

**`POST /system/user/list`**（POST，不是 GET）

源码 `SysUserController.java`：类上 `@RequestMapping("/system/user")`，方法上 `@PostMapping("/list")`

返回 `TableDataInfo`：

```json
{
  "total": 2,
  "rows": [ {"userId":1,"loginName":"admin","userName":"若依","deptId":103,"status":"0","createTime":"2021-09-15 10:23:41"} ],
  "code": 0,
  "msg": null
}
```

**注意 `code` 是 `0`，`msg` 是 `null`，不是 `200` / `"查询成功"`。**

源码 `BaseController.getDataTable()`：

```java
protected TableDataInfo getDataTable(List<?> list) {
    TableDataInfo rspData = new TableDataInfo();
    rspData.setCode(0);          // 写死 0
    rspData.setRows(list);
    rspData.setTotal(new PageInfo(list).getTotal());
    return rspData;
}
```

4.6.2 / 4.7.8 / 4.8.0 / 4.8.3 四个版本都是 `setCode(0)`，不要统一改成 200。

> 单条结果用 `AjaxResult` 时才是 `{"code":200,"msg":"操作成功"}`。两种结构不是一回事，别混。

分页参数：`pageNum` `pageSize` `orderByColumn` `isAsc`

## 三、微服务版（R8，RuoYi-Cloud v3.6.8）`[已核验 2026-10-29]`

> 样本：Gitee tag v3.6.8（**2026-03-30 重发**，Spring Boot 4.0.3 / Spring Cloud 2025.1.0 / Java 17）。
> 与 R6/R7 最大的差异：**配置在 Nacos，不在本地 yml**；网关按前缀路由到各微服务。

### 3.1 入口与前缀 `[已核验]`

Nginx `19108` **只反代 `/prod-api/`**（`proxy_pass http://127.0.0.1:19208/`，去掉前缀），
根路径是 SPA 静态页（`try_files $uri $uri/ /index.html`）。所以对外 URL 是
`/prod-api/<网关路由>/...`，网关内部看到的路径没有 `/prod-api`。

网关路由（`/actuator/gateway/routes` 实测）：

| 对外前缀 | 后端服务 |
|---|---|
| `/prod-api/auth/**` | ruoyi-auth (9200) |
| `/prod-api/code/**` | ruoyi-gen（验证码 RouterFunction，9202） |
| `/prod-api/schedule/**` | ruoyi-job (9203) |
| `/prod-api/system/**` | ruoyi-system (9201) |
| `/prod-api/file/**` | ruoyi-file (9300) |
| `/prod-api/ruoyi-*/**` | 服务发现路由（`ruoyi-auth` / `ruoyi-system` / …） |

> 旧文档「R8 没有 `/prod-api` 前缀」是错的：那是**后端直连**的形态；经 Nginx 的对外入口有前缀。

### 3.2 登录与验证码 `[已核验]`

| 方法与路径 | 行为 |
|---|---|
| `GET /prod-api/code` | `{"msg":"操作成功","code":200,"captchaEnabled":false}`（R8 关闭了验证码） |
| `POST /prod-api/auth/login` | JSON `{"username":"admin","password":"admin123"}` → `{"code":200,"data":{"access_token":"eyJ...","expires_in":720},"msg":null}` |

- Token 在 **响应体** `data.access_token`，不下发 Cookie；后续请求用 `Authorization: Bearer <token>`。
- 匿名访问受保护接口：HTTP **200** + `{"code":401,"msg":"令牌不能为空"}`。
  （注意与 RuoYi-Vue 的「请求访问：X，认证失败」文案不同，扫描器判定要兼容两种。）
- 登录接口是 `/auth/login`，**不是** `/login`；`POST /prod-api/login` 返回
  `{"code":500,"msg":"404 NOT_FOUND \"No static resource login ...\""}`。

### 3.5 错误页形态（Cloud 与单机/Vue 都不同）`[已核验]`

不存在的前缀/资源返回 HTTP **200** + 统一 JSON：

```json
{"code":500,"msg":"404 NOT_FOUND \"No static resource monitor/job/edit for request 'http://127.0.0.1:19108/monitor/job/edit'.\""}
```

- 路径回显在 `msg` 里（扫描器必须按「资源不存在」排除，不能拿路径名当关键字）。
- `code=500` 不代表业务层可达 —— 这是网关的 404 包装，和单机版的业务 500 语义相反。

## 六、契约自检（以 R2 v4.6.2 为例）

```bat
curl -i http://127.0.0.1:19102/login
curl -i "http://127.0.0.1:19102/captcha/captchaImage?type=math"
curl -s -X POST http://127.0.0.1:19102/system/user/list -d "pageNum=1&pageSize=10"
curl -s -X POST http://127.0.0.1:19102/common/upload -F "file=@test.txt"
```

期望：
1. `/login` → 200 + HTML，含 `Copyright © 2018-2021`，`Server: nginx/1.2x.x`
2. `/captcha/captchaImage?type=math` → 200 + `Content-Type: image/jpeg` + 约 2.9 KB
3. `/system/user/list` 未登录 → 302，**且 Location 必须带端口**（`http://127.0.0.1:19102/login`，不是 `:80`）
4. `/common/upload` 登录后 → 只有 `fileName` 和 `url`（4.6.2 的契约）

> 第 3 条是 Nginx 配置的试金石：`proxy_set_header Host $host` 会丢端口，必须是 `$http_host`。
