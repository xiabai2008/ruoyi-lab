# 05 真实感清单

一个系统真不真，不取决于代码写得多好，取决于**有没有一堆说不清来历但确实存在的东西**。真实企业系统里永远有：三年前的备份、忘了删的测试账号、注释掉的旧配置、凌晨三点的一条错误日志。

下面按类别给清单，每个站点按自己的定位取用。

**造数据的三条要求**：
1. 姓名用真实中文姓名（张伟、李娜、王建国），不要 `test01` `user001`
2. 部门名像真的（"生产制造部"、"华东大区销售中心"、"后勤保障科"），不要"部门1"
3. `create_time` 落在**上线日到昨天**之间，且分布不均（工作日多、周末少、月初月末有集中）

## 二、日志

若依默认 logback 已经在 `logs/` 下产出 `sys-info.log` `sys-error.log` `sys-user.log`。要求：

- **时间跨度覆盖上线日至今**，不是只有今天几条
- `sys-info.log` 里要有：启动 banner、定时任务执行记录、数据源连接池状态
- `sys-error.log` 里要有真实异常堆栈，比如：
  - `NullPointerException` 在某个业务方法里（配 8-15 行堆栈）
  - `java.sql.SQLException: Duplicate entry` （导入重复数据时产生）
  - `org.springframework.dao.DeadlockLoserDataAccessException`（并发写）
- `sys-user.log` 记录登录/登出，有失败记录（比如某个账号连错 3 次密码）
- Nginx `access.log` 用 combined 格式，混入正常浏览器 UA、微信内置浏览器 UA、少量 `python-requests`（运维脚本调接口）

**不要**在日志里出现 `sqlmap`、`nmap` 这类工具 UA，太刻意。

## 三、备份与导出文件

这是真实系统里最常见、也最容易被忽略的东西。放在 Web 可达目录下：

| 文件 | 位置 | 内容 | 大小 |
|---|---|---|---|
| 建库脚本 | `/backup/ry_20210915.sql` | 完整表结构 + 部门/角色/菜单基础数据 | 180~320 KB |
| 数据备份 | `/backup/数据备份_20220301.sql` | 部分业务表数据 | 200~500 KB |
| 导出报表 | `/profile/upload/2021/12/15/设备台账导出_20211215.xlsx` | 真实表头 + 数据 | 40~120 KB |
| 配置备份 | `/backup/application.yml.bak` | 含数据库口令明文 | 8 KB |

R1 的 `/backup/` 目录要能直接列目录（`autoindex on`），R2 R4 只能猜文件名。

## 四、配置文件里的"渣"

`application.yml` / `application-druid.yml` 里保留这些痕迹：

```yaml
# 数据源配置
# 测试环境：jdbc:mysql://10.10.1.22:3306/ry?useUnicode=true
# 生产环境已切换，测试库保留只读账号  test_read / Test@123
spring:
  datasource:
    druid:
      master:
        url: jdbc:mysql://127.0.0.1:13307/ry_r2?...
        username: root
        password: Root@2021
```

- 注释掉的旧环境地址（内网 IP）
- 明文口令
- `# TODO: 迁移到配置中心` 这类开发遗留注释
- `stat-view-servlet` 的 `login-username` / `login-password`

## 五、账号体系

真实系统的账号状态是混乱的：

- `admin` 一直用初始口令（R1 R2 R4）
- 有 3~8 个"离职未停用"账号，`status=0` 但 `login_date` 停在两年前
- 有 2~3 个共用账号（`bangongshi`、`kefu01`），昵称写着"办公室公用"
- R1 有个 `test` 账号挂在管理员角色上
- R5 严格：无弱口令，但有一个 `ops_monitor` 只读账号

## 六、上传目录

`profile/upload/YYYY/MM/DD/` 按日期分目录（这是若依默认行为，会自然形成）。

放真实文件：
- 设备照片（jpg，几十 KB）
- 合同扫描件（pdf，200 KB~1 MB）
- Excel 表格
- 文件名保留原始中文名（若依上传后是 `原名_时间戳A001.xlsx`）

**不要**放 webshell、不要放 `.jsp`，那太刻意。

## 七、证书

- 自建内部 CA（`CN=XX集团企业根CA`），有效期 10 年
- 站点证书 `CN=oa.zhongding.local` 之类，有效期 1 年，签发日 = 上线日
- R3 R5 R6 走 HTTPS
- 证书链完整，浏览器只报"未知颁发机构"，不报"证书过期"

## 八、监控与探活

| 站点 | 开放情况 |
|---|---|
| R1 | Druid 监控 `/druid/index.html`（官方默认 `enabled: true`，Druid 自己的账号 `ruoyi` / `123456`）。**未登录若依时访问会 302 到 `/login`**——ShiroConfig 里没有 `/druid/**` 的匿名规则，被 `/**` 兜底拦了。要看到监控页必须先有若依会话 |
| R2 | Springfox 文档 `/swagger-ui/index.html`、`/v2/api-docs`（pom 自带） |
| R3 | `/logs/` 静态映射，`sys-info.log` 可直接下载（Druid 和 swagger 都被关掉了） |
| R4 | Springfox 文档 `/swagger-ui/index.html`、`/v2/api-docs` 在**登录后**可访问。未登录会被 Shiro 的 `/**` 兜底拦成 302——ShiroConfig 的匿名清单里没有 swagger 相关路径 |
| R5 | SpringDoc 的 `/v3/api-docs` 被 Shiro 拦截，匿名访问 302 到登录页 |
| R7 | `/actuator/env` `/actuator/heapdump` `/actuator/mappings` 开在 19207（Vue 版依赖需核实后确认） |
| R8 | `/actuator/gateway/routes` + Nacos 控制台 |

> 单机版（R1~R5）**没有 actuator**，4.x 全部版本的 pom 里都没这个依赖。别给它加，加了就是假系统。

## 九、Web 根目录的遗留物

按站点分配，不要每个站点都堆满：

- R1：`.svn/entries`、`backup/` 目录可列、`robots.txt`
- R2：`.git/HEAD`（能读到 `ref: refs/heads/master`）、`swagger-ui.html` 可打开、`robots.txt` 列了 `/backup/`
- R3：`logs/` 通过 Nginx 静态映射可访问
- R4：`application.yml.bak` 在 `/backup/`
- R7：前端 `dist` 带 `.map`、`.DS_Store`
- R8：Nacos 控制台无鉴权

## 十、时间线一致性（最容易翻车）

造完必须自查，不一致立刻露馅：

1. 所有文件 `mtime` 不要全是今天。jar 的 mtime 应该是构建日，日志的最后一行应该是昨天或今天凌晨
2. SQL 里 `create_time` 最大值不早于上线日、不晚于今天
3. 日志时间戳严格递增，不允许出现未来时间
4. git commit 时间分散在上线日之后，不要 500 个文件一个 commit 一个时间点
5. 站点证书 `Not Before` = 上线日

## 十一、"企业文档"要有的东西

每个站点的 `docs/Rxx/` 下放 4~6 份，写成真实交付文档的样子：

- `系统部署说明.md`：服务器配置、端口、目录、启动方式（含真实的内网 IP 段）
- `数据库设计说明.md`：表清单、字段说明（不用全，核心 8~10 张）
- `接口对接文档.md`：外围系统对接清单（这份最有用，能解释 04 章的契约从哪来）
- `运维交接记录.md`：历次变更（"2022-03 扩容磁盘"、"2023-11 升级到 4.7.8"）
- `用户操作手册.md`：给业务人员看的，截图可以不放
- `版本发布记录.md`：版本号、发布日期、变更点

**这些文档里不要出现任何"已知问题""安全风险""建议加固"的段落。**

## 十二、验收：怎么判断"够真"

不看代码，找一个不懂技术的人看三分钟，如果他能说出"这像是我们公司以前用过的那套系统"，就合格了。具体三条：

1. 登录页有没有那种"2018-2021"的老气横秋的版权行
2. 首页有没有 200 多条菜单、十几个模块、一堆看不懂缩写的子系统
3. 点进用户管理，列表里是不是一堆真名、真部门、真手机号（脱敏格式 `138****5678`）
